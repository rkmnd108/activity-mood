## 入力画面の確認方法（Phase 3対応）

1. 「今から開始」で日本時間の現在日時が表示され、終了時刻欄がないことを確認します。
2. 「あとから記録」で開始日・開始時刻・終了時刻を変更します。初回は現在日時が入ります。
3. やったことが1つだけ選択されること、「その他」のときだけ必須の自由入力欄が出ることを確認します。
4. 気分の初期値は50です。スライダーを動かし、0〜100・10刻みの数値と指定の5段階の色を確認します。
5. 体調の「良い」「普通」「悪い」を選びます。行動・体調は未選択から始めます。
6. 「開始する」または「保存する」を押します。未選択や「その他」の空欄・空白だけの入力には入力を求めます。
7. 保存が完了すると成功メッセージと記録が表示されます。

保存前の入力内容は画面切り替え中は維持しますが、再読み込みでは消えます。保存済み記録は残ります。

終了日は保持し、同じ日・同じ時刻や逆順の記録は保存しません。18時間以上・他記録と重複する場合は保存前に確認します。

## Phase 3の使い方とデータ保護

- 普段の利用URLは `http://127.0.0.1:4173` です。同じブラウザ・同じURLで開いてください。
- Chrome、アプリ内ブラウザ、iPhoneは別々の保存領域です。自動同期はしません。URLのホストやポートを変更した場合も保存領域が異なります。
- 「今から開始」はボタンを押した現在の日本時間で開始します。「終了」は押した現在時刻で終了します。分単位なので、開始と同じ分の終了は拒否します。時間を置くか、記録を編集してください。
- 「あとから記録」は開始日・開始時刻・終了日・終了時刻を入力します。終了時刻が開始より前なら翌日を補います。一度終了日を手動変更した後と編集画面では、自動補完せず入力した終了日を維持します。
- 「今日の記録」は6:00〜翌5:59に該当する記録を開始日時の新しい順に表示します。「保存した記録（すべて）」を開くと、従来の終了済み全件一覧も確認できます。進行中は上部にも表示します。
- 記録を押して編集できます。進行中の記録は、編集画面で「この記録を終了済みにする」を選ぶと終了日時を指定できます。
- 削除には確認が必要です。削除は元に戻せません。「キャンセル」で削除しないことを確認してください。
- IndexedDBは `activity-mood`、バージョン1、ストア `records` です。初回作成のみで、既存DBの削除・初期化はしません。
- `endDate` と `revision` をデータに追加しました。編集時の競合は拒否します。別タブで記録が変わった場合は入力を残して案内し、勝手に上書きしません。
- 書き込み完了を待って成功表示します。失敗時は入力を残し、理由を表示します。DBの自動削除や再作成は行いません。
- バックアップは「出力」から保存できます。ブラウザのサイトデータを削除すると記録も失われるため、削除しないでください。

## 印刷レイアウトのルール

- 色の付いたブロックの開始位置・高さは実時間に比例します。0:00で日を分けません。
- 短時間の記録は、実時間の形状にコンパクトな1行ラベルを重ねます。左端の目印が開始位置です。通常・短時間・日界分割のいずれも、行動ブロック内に開始・終了時刻は表示しません。
- 通常は色付きブロック内に行動アイコン・行動名・気分・体調を1行で表示します。文字が入らない短い区間は補助ラベルを使うため、そのラベルの高さは活動時間を意味しません。長い名称や衝突で読みづらくなる場合は、日時付きの詳細ページへ回します。
- 重複記録は同じ日の列の中で横に並べ、縦の時間位置は変えません。レーン分割は重複が連続する区間だけに限定し、他の時間帯は列幅を戻します。
- 6:00の日界で分割するのは表示だけです。元の記録は1件のままです。
- 進行中は終了時刻が未確定のため、印刷・平均の対象外です。記録を終了し、印刷用画面を再読み込みすると反映されます。
- 平均は開始所属日の終了済み記録の算術平均です。欠測日の前後は線をつなぎません。色の境界は25・45・55・75で、計算値をそのまま色判定に使います。
- A4横1ページを基本とし、情報を小さく押し込める代わりに必要な詳細ページを追加します。極端に長い名称も省略せず、複数ページへ折り返します。
- 印刷はDBを読み取るだけで、記録の編集・削除・外部送信はしません。

## Phase 6：バックアップ・復元

1. 通常URLを再読み込みし、下部の「出力」を開きます。入力途中の内容がある場合は先に保存してください。
2. 「バックアップを準備」→「JSONファイルを保存」を押します。進行中を含む全記録が対象です。準備した時点のデータなので、記録の変更後はもう一度準備してください。
3. 保存先に activity-mood-backup-日付.json があることを確認してください。アプリは端末への保存完了を自動判定できません。
4. 復元はJSONファイルを選び、「現在のデータに追加」または「現在のデータを置き換える」を選択し、「復元内容を確認」を押します。
5. 現在の件数・処理後の件数・追加／スキップ件数を確認します。先頭200件の内容を展開できます。検証は表示数に関係なく全件に対して行います。
6. 追加は「追加する」で実行します。同じIDは内容が異なっていても上書きせずスキップします。別のIDで時間が重なる記録や18時間以上の記録も、バックアップの内容として復元します。
7. 置き換えは「処理前のJSONを保存」で退避し、端末への保存を確認してから「最終確認へ」→「置き換える」を押します。空のバックアップへの置き換えは0件になります。
8. 全削除は折りたたまれた「全記録の削除」内から操作します。件数確認→最終確認の2段階です。途中のキャンセルでは記録を変更しません。

復元後に進行中が2件以上になる場合、不正な値・同じファイル内のID重複がある場合は拒否します。確認中に別タブで記録が変わった場合も実行せず、最初から確認し直してもらいます。
記録を編集中・保存中の場合は復元／全削除を始められません。新規記録の入力途中の内容は維持します。
置き換え後に古い編集画面から上書きされないよう、復元した記録の版番号を更新します。行動・日時・気分・体調・作成日時・更新日時は維持します。
書き込みは1つのIndexedDBトランザクションで行い、途中の失敗は全体を取り消します。DBの削除やバージョン変更はありません。

JSONはこのアプリの形式・バージョン1に対応し、50MB以下を読み込めます。旧仕様書の例のような、形式情報や終了日などが欠けた手書きJSONには対応しません。新しい項目や将来のバージョンは、黙って無視せず拒否します。

## Phase 7：ホーム画面・オフライン

1. このPCで通常URLを開き、「出力」の「ホーム画面・オフライン」を確認します。
2. 「オフラインで使う準備ができています。」が表示されたら、初回の保存は完了です。
3. PCのChromeでインストールのメニューが表示される場合は、そこからアプリとして追加できます。インストールしなくても、準備済みの同じURLをオフラインで開けます。
4. 更新時は「更新を確認」を押し、新しい版が表示されたら、入力を保存して「新しい版に更新して再読み込み」を押します。入力中の記録がある場合は更新を止めます。他のタブも保存後に再読み込みしてください。

通信断でも起動・記録・編集・削除・週間表示・PDF用画面・JSONバックアップ／復元を使えます。PDFの保存操作そのものはブラウザ／OSの印刷機能です。
画面用キャッシュは、このアプリと設置先のURLを含む専用名で管理します。更新時には同じ設置先の古い画面キャッシュのみ削除し、IndexedDBは変更しません。JSONファイルやテストページをキャッシュ対象にしません。
ネット接続表示はブラウザの接続情報です。PCのローカルサーバーだけを止めた場合は、ネット接続表示が変わらなくても、保存した画面から起動できます。

iPhoneでホーム画面へ追加する操作はSafariの共有メニューから行います。ただし現在の127.0.0.1はこのWindows PCの確認用URLです。iPhoneから同じURLを開いても、このPCのアプリにはつながりません。
iPhoneでの実機確認には、iPhoneからアクセスできるHTTPSの配信先などを別途用意する必要があります。公開・デプロイはまだしていません。
Service WorkerのHTTPS要件とローカル開発の例外は [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API) を参照できます。

### Phase 7の検証

アプリ内ブラウザの専用ポート4174で、専用DBと架空データを使用しました。
- 初回の全ファイル取得とService Workerの有効化。
- 専用サーバー停止中に、キャッシュ対象外への通信が失敗すること。
- 停止中に新しいタブからアプリを起動し、出力画面まで開けること。
- 停止中の読込・編集・JSON往復・PDF用画面生成・架空の1記録の単独削除・復元。

テスト用ページはキャッシュしないため、テストを始めるときは専用サーバーを起動してください。オフライン検証はページを開いて準備完了後に専用サーバーを停止して行います。更新検証は、その後サーバーを再起動し、VERSIONを新しい値に変えて実行します。同じ版のままでは「新版が待機していません」となります。
Chromeへのインストール操作、iPhone Safari／ホーム画面起動、実際のオフライン印刷・ファイル保存はPhase 8で確認が必要です。

## Phase 8：総合確認

専用Chromeプロファイルと専用ポート4174で、通常の保存領域とは分離したテストを実行しました。Phase 3の保存・編集・競合・単独削除13件、Phase 6のJSONバックアップ・復元・2段階削除18件、Phase 8の画面幅18件が成功しました。

画面幅は320px、390px、768pxで、記録・入力・週間・出力の横はみ出しがないこと、JSON保存リンク、削除確認のキャンセルを確認しました。日付・平均・PDFのNode.jsテスト28件も成功しています。

通常のChromeプロファイル、通常URLのIndexedDB、ユーザーの記録はテストで変更していません。テストの途中で見つかった保存操作の競合はアプリではなく、画面幅テストが入力選択後の非同期UI更新を待っていなかったことが原因でした。検証コードだけを修正し、実アプリの保存処理は変更していません。

Chromeの通常UIからのインストール操作、iPhone Safariでのホーム画面追加、iPhone実機でのオフライン起動、実際のPDF印刷・ファイル保存は未確認です。現在の `127.0.0.1` はこのPCだけの確認用URLなので、iPhone実機確認にはiPhoneから到達できるHTTPS環境が必要です。公開やデプロイは行っていません。
